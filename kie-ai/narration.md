# Озвучка: Kie.ai + AI Video Pipeline

## 00:00–00:20 · Что сегодня строим
Сегодня мы не просто сделаем один ролик. Мы подключим Kie.ai сразу к трём рабочим агентам: Codex, Claude Code и Hermes. А затем соберём повторяемый процесс, в котором агент сам проходит от референса и раскадровки до готового видео и проверки результата.

## 00:20–00:40 · Карта системы
Логика системы простая. Ты ставишь задачу агенту. Агент работает на твоём компьютере или VPS. Через API или MCP он обращается к Kie.ai, запускает нужную модель, получает результат и возвращает тебе готовый файл. Важно понять эту цепочку один раз.

## 00:40–01:00 · API, MCP и Skill
Три слова, которые нельзя путать. API — это способ связаться с сервисом. MCP — набор инструментов, которыми агент может пользоваться. Skill — сохранённый навык: инструкция, как правильно применять эти инструменты для конкретного результата. Связь, инструменты и навык — это три разных слоя.

## 01:00–01:20 · Pipeline и Workflow
Pipeline — это конвейер шагов: сначала первое действие, потом второе, потом третье. Workflow шире. Он включает сам pipeline, проверки, память, обработку ошибок и возврат на предыдущий шаг. Наша цель — не разовая генерация, а workflow, который можно запускать снова.

## 01:20–01:40 · Мост к машине
Чтобы агент мог реально работать, ему нужен доступ к машине. Remote Desktop Commander создаёт мост между ChatGPT и твоим Mac, Windows или VPS. После этого агент может видеть окружение, работать с файлами, запускать команды и устанавливать нужные компоненты.

## 01:40–02:00 · Изучаем окружение один раз
Первый раз агент должен изучить машину: операционную систему, Git, Node.js, Python, Docker, структуру проектов и рабочие каталоги. После проверки он сохраняет карту окружения. Тогда в следующих задачах он уже знает, где находится и чем может пользоваться.

## 02:00–02:20 · Research Once Protocol
Главное правило урока: сложную тему исследуем один раз. Агент сначала читает первоисточники, сравнивает практические решения, делает минимальный тест, фиксирует то, что реально сработало, и сохраняет знание как skill или project memory. Повторное исследование нужно только при изменении API, модели или при реальной ошибке.

## 02:20–02:40 · Документация Kie.ai
Перед установкой агент читает официальную документацию Kie.ai. Он должен понять доступные модели, создание задач, загрузку файлов, Task ID, polling, форматы ответов и ограничения. Это защищает нас от выдуманных endpoint, старых model ID и случайных параметров.

## 02:40–03:00 · API key безопасно
API key не отправляем в обычный чат и не вставляем в URL. Агент создаёт безопасную одноразовую форму или использует существующий Secret Bridge. Он должен проверить только факт успешной авторизации. Значение секрета не должно появляться ни в ответе, ни в логах.

## 03:00–03:20 · Smoke test
До видео запускаем самый дешёвый smoke test. Агент проверяет авторизацию, баланс и одну простую генерацию. Если этот маленький тест не проходит, бессмысленно запускать дорогую видеомодель. Сначала добиваемся стабильной связи, потом двигаемся дальше.

## 03:20–03:40 · Не пишем всё с нуля
Следующий принцип: сначала ищем готовые решения. Агент исследует существующие MCP, CLI и skills, смотрит свежесть репозитория, issues, поддержку моделей, зависимости и безопасность. Только после этого решает, использовать готовое решение, адаптировать его или собирать своё.

## 03:40–04:00 · Репозитории-кандидаты
Для Kie.ai можно начать аудит с felores slash kie-cli-mcp. Для video workflow полезны ai-video-skill, ai-video-storyboard-skill и video-to-skill. Это не команда установить всё подряд. Это стартовая точка для исследования агентом и выбора лучшего решения под вашу архитектуру.

## 04:00–04:20 · Три агента, разная память
Один и тот же Kie.ai tool layer можно дать Codex, Claude Code и Hermes. Но память у них разная. Поэтому правила проекта, найденные решения и рабочие skills нужно зафиксировать отдельно в памяти каждого агента, чтобы он не начинал следующую задачу с нуля.

## 04:20–04:40 · Декомпозируем видео
Не пишем агенту просто: сделай видео. Большую задачу разбиваем на измеримые этапы: персонаж, раскадровка, сценарий, выбор модели, исследование промптинга, production prompt, генерация и QA. Чем яснее этапы, тем проще понять, где именно возникла ошибка.

## 04:40–05:00 · Identity Card
Берём главный reference персонажа. Агент фиксирует identity card: форму лица и головы, волосы или их отсутствие, бороду, возраст, комплекцию, одежду и другие признаки, которые нельзя менять. Это становится постоянным визуальным контрактом для следующих кадров.

## 05:00–05:20 · Character Consistency
Если лицо начинает плыть, не делаем десять случайных повторов. Агент исследует character consistency именно для используемой модели и способа генерации. После теста он обновляет правила и сохраняет рабочее решение. Следующая генерация уже идёт по проверенному протоколу.

## 05:20–05:40 · Раскадровка N=9
Теперь создаём N равно 9: девять отдельных кадров одного персонажа и одной сцены. Меняются ракурс, действие и положение камеры, но идентичность героя, одежда, визуальный мир и логика сцены остаются стабильными. Это наши референсы будущего видео.

## 05:40–06:00 · Сценарий на 10 секунд
После кадров пишем сценарий. Для десятисекундного ролика удобно разбить действие на три участка: ноль–три, три–семь и семь–десять секунд. Отдельно описываем движение героя, камеру, реплику, фон и финальное действие. Сценарий пока пишется для человека, не для видеомодели.

## 06:00–06:20 · Проверяем модель
Перед генерацией агент снова идёт в актуальную документацию Kie.ai. Он проверяет точный model ID, допустимую длительность, режим работы с reference images, resolution и ограничения. Мы не доверяем памяти агента там, где API мог обновиться вчера.

## 06:20–06:40 · Research Once для MiniMax H3
Если выбрали MiniMax H3, агент один раз изучает именно H3: структуру prompt, управление движением, camera language, использование референсов, речь и доступные параметры. Общие советы по видеогенерации здесь хуже, чем правила конкретной модели.

## 06:40–07:00 · Production Prompt
Только теперь сценарий превращается в production prompt. Он учитывает синтаксис, сильные стороны и ограничения выбранной модели. Поэтому один человеческий сценарий может породить разные prompts для H3, Veo, Seedance или другой модели. Сценарий и prompt — не одно и то же.

## 07:00–07:20 · Task ID и polling
Агент подготавливает девять reference images, загружает их правильным способом, создаёт задачу в Kie.ai и сохраняет Task ID. Затем делает polling с нормальным интервалом, ждёт завершения, получает result URL, скачивает файл и проверяет, что видео действительно открывается.

## 07:20–07:40 · QA Loop
Генерация не заканчивается получением MP4. Агент сам проверяет идентичность персонажа, руки, синхронизацию речи, движение камеры, continuity и соответствие сценарию. Если есть дефект, он диагностирует причину и возвращает проблему на нужный этап workflow, а не перегенерирует вслепую.

## 07:40–08:00 · Сохраняем skill
Когда получили рабочий результат, весь процесс фиксируется как reusable skill: reference, identity, N=9, script, model research, production prompt, generation и QA. Следующее видео начинается не с чистого листа. Так из одной генерации постепенно получается собственный AI-контент-завод.
